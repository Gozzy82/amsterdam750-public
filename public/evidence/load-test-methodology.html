Loadtestmethodologie en bewijsstatus

Deze pagina maakt expliciet onderscheid tussen de door de projectauteur gerapporteerde resultaten en de bronartefacten die in de publieke repository controleerbaar zijn.

Gerapporteerde testrun

Tool Azure Load Testing
Duur 5 minuten
Doel De serverless pre-registratieflow
Volume Meer dan 126.000 succesvolle HTTP-requests
Gemiddelde throughput Circa 420 requests per seconde over de volledige run
Mislukte requests 0% volgens de samenvatting van de run
Latency Gerapporteerde p95-responstijd onder 650 ms

Meetdefinities

  • Een succesvolle request is een request die volgens de loadtest geen transport- of HTTP-fout opleverde.
  • “0% fouten” betekent niet dat de volledige productieflow onder alle omstandigheden foutloos is.
  • De p95 is de grens waarbinnen 95% van de gemeten responstijden viel.
  • De gemiddelde throughput is afgeleid uit 126.000 / 300 = 420 requests per seconde.

Benodigde bronartefacten

Bewijsstatus: onvolledig. De oorspronkelijke Azure Load Testing-export, het testschema, de geanonimiseerde testdata en de infrastructuurversie zijn nog niet in deze checkout aanwezig. Zonder die bestanden zijn de cijfers transparant beschreven, maar niet onafhankelijk reproduceerbaar.

Voor volledige verificatie moet de publieke repository bevatten:

  1. het gebruikte JMeter- of YAML-testschema;
  2. de Azure Load Testing CSV- of dashboardexport;
  3. de exacte commit en infrastructuurconfiguratie van de testrun;
  4. regio, runtime/SKU, warmingbeleid en concurrencyprofiel;
  5. een beschrijving van validaties waarmee een request als functioneel succesvol gold.

Acceptatiecriteria voor een herhaling

  • De test gebruikt geen echte persoonsgegevens.
  • Alle responses worden op status en functionele uitkomst gevalideerd.
  • Foutpercentage, p50, p95, p99 en throughput worden geëxporteerd.
  • De gebruikte codecommit en infrastructuurversie worden vastgelegd.
  • Geheimen, tokens en productie-identiteiten worden niet gepubliceerd.
